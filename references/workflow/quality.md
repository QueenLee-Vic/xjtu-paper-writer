# 08 最终质量检查

按实际任务检查，不适用项标注不适用并简述原因。

| 检查域 | 通过条件 |
| --- | --- |
| 要求覆盖 | 教师及用户关键约束可逐项对应，冲突已解决 |
| 内容 | 文章类型、结构、术语、公式、单位及论证一致 |
| 证据 | 实验结果可追溯；引用真实且支持相邻论点；未核实条目隔离 |
| 图表 | 数据图可复算；示意图有标识；编号、题注及正文引用对应 |
| 润色保护 | 技术事实和原始结论未被擅改 |
| 仅排版保护 | 正文、数字、公式、图表文字、参考文献及顺序保持不变 |
| DOCX | 文件可打开；语义样式正确；有条件时完成视觉检查 |
| 交付 | 原稿保留、输出可定位、已知限制与未完成项清楚 |

报告区分“通过”“未通过”“未验证”“不适用”，禁止把未执行的检查写成通过。关键数据、引用或内容保真检查未通过时交付物必须标明问题；不能宣称整篇学术验收。仅排版若格式及内容保真检查通过，可报告“排版范围通过”，原稿证据疑点另列，不擅自修正文献。无文档工具时可以交付正文或排版方案，但不得把 Markdown 改扩展名当作 DOCX。


规则任务另检查：需求来源是否区分用户/文档/默认/关键待定；模板是否按属性决策及内容格式隔离；默认参数是否带来源和验证状态；阶段选择是否符合模式；局部任务是否保护无关范围。缺少原始参考文档时不能报告模板参数已验证。


配置预览另核对：有效属性来源与五级优先级一致；原始状态保留；非法值/单位、候选和同级冲突不能静默执行；apply_properties 仅含授权且已解决的格式属性。预览和 writer_contract 不是文档写入证明，write_performed 必须为 false；既有 DOCX 与 Phase 3A 分析文件须保持不变。


实际文档写入与配置预览分开检查，按照 [写入保真合同](../standards/docx-writing.md) 比较结构、OMML、媒体、关系和未修改部件，并核对格式授权日志。只有实际发布的格式化产物 write_performed=true；完整就绪状态及公式待验证不得因此改写。


渲染生成、PDF bbox 几何量测、Agent 抽查、用户人工确认和 Microsoft Word 验证分别报告。实际长公式溢出或数学字体替换不能因结构保真通过而忽略。只有确实执行的样本允许标记为当前渲染环境通过。


Phase 3B-2C 需分别对源文件/历史输入/输出 DOCX 和 PDF 核对缺项，记录版本差异；长公式溢出、字体回退或不可可靠识别的区域须阻止完整排版验收。分页判断以实际页面关系为依据，不只看页数。


配图另核对 A/B/C/D 类型、必要性和源材料，不把文件存在当数据/实验真实性证明。示意图标识、来源/权限、节点连接、文字边界、输出哈希和人工语义/视觉项分别记录；外部模拟调度不算实际调用。没有实际图片不能伪造 DOCX 插图路径。

数据图另核对文件/结构/实际 artist 数据/科学真实性四层，合成测试醒目标识；缺值、排序、统计含义与 n/单位有记录。插图以 [授权增量保真](scientific-figures.md) 验证：剔除精确授权新增项后原文档/关系/部件必须恢复一致；未授权变化阻止发布。实际渲染检查图片、题注邻接、比例与分页，不能以 PNG/SVG 保存成功代替视觉验收。

润色按 [学术润色保护](academic-polishing.md) 分别报告自动保护、模拟合同、实际 Agent 语义审查和 DOCX 写入验证。自动 token 不变不能证明含义不变；每个变更单元要绑定前后哈希、逐维度片段与理由，缺失/不确定/模拟评审不得发布，语义变化拒绝。只有已还原的文本可交付，不把公式占位符或未知 OMML 映射当成品；Phase 4B-1 的 DOCX 写入标记保持未实现，实际写入另按执行合同验证。

DOCX 润色计划按 [映射合同](../standards/docx-text-mapping.md) 核对源 SHA、稳定 ID/结构定位、Run 原格式、精确字符范围及重新计算的 B1 审查；评审还绑定全文候选/任务，不能靠缓存 ready 或布尔值放行。只读阶段的源保真不等于修改后保真、页面或 Word 验证；4B-2A 预览全部 write_allowed=false，不改写历史标记。


实际润色写入按 [局部写入合同](../standards/docx-polishing-writing.md) 检查：源/映射/任务/候选/审查版本一致、全部目标重新定位、实际新文字符合计划；只逆还原已核实授权补丁后，全主 XML canonical 与原件相同，其他部件原字节相同，并独立检查原 rPr/pPr、OMML、表格、图片、关系/辅助故事。失败阻止原子发布，不允许静默部分写入。结构有效、授权文本与格式保真、PDF 渲染、页面抽查及 Word 验证分层；原有分页缺陷应记录为基线，不能借润色更改格式或报告已修复。


Phase 5A 的完整任务验收须区分当前 Agent 实际写作/语义判断、脚本模块组合、合成任务/数据和独立宿主 Skill 调用。当前只验证显式加载后的手动调度；自动发现/独立入口不升级为通过。实际轨迹、四文体与三模式及八维结果见 任务实跑报告。

新稿转换后的表格必须在页面中核对文字，不因 ZIP/XML 或正文快照通过就认为可见。当前 Pandoc 的未指定列宽曾造成 PDF 表格裁切，需在新稿生成前给出可靠宽度；不自动改已有 Word 表格或学术数据。PDF 普通阅读顺序有差异时，结合结构保真、原始/保留布局文字、明确表格区域及页面图核查，不能直接删文本或把失败扫描强改通过。字符单位缩进的 OOXML 设置与实际渲染效果分别报告，不能无依据添加固定磅值以制造视觉通过。


## 工作区运行合同

工具须传 `--workspace`，用户文件相对授权工作区解析；规则和资源相对安装根解析。所有原有范围授权、哈希绑定、保护与保真检查继续生效。详细入口见 [安装说明](../../INSTALL.md)。
